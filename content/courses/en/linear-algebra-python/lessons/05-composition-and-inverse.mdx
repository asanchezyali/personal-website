If a matrix represents a transformation, then the product of two matrices must necessarily mean
**applying one and then the other**. Matrix multiplication is nothing else.

## The order of application

The expression $AB$ indicates that $B$ is applied first and $A$ afterwards. It reads from right to
left, just as function composition $f(g(x))$ does.

```python
import numpy as np

R = np.array([[0, -1], [1, 0]])   # 90° rotation
S = np.array([[2,  0], [0, 1]])   # stretch the x axis twofold

R @ S     # array([[ 0, -1], [ 2,  0]])
S @ R     # array([[ 0, -2], [ 1,  0]])
```

The results differ. Stretching and then rotating is not the same as rotating and then stretching, a
distinction that is evident from the geometric reading and entirely opaque if one attends only to
the rows-by-columns rule.

That is the underlying reason why matrix multiplication **is not commutative**. It is not a quirk of
algebra: function composition is not commutative either.

## The inverse transformation

If $A$ transforms the plane, it is natural to ask whether a matrix exists that restores it to its
original state. That matrix is the **inverse**, $A^{-1}$, and it satisfies:

$$A^{-1}A = I$$

where $I$ denotes the identity, the matrix that leaves the plane unchanged.

```python
A = np.array([[2, 1],
              [1, 1]])

A_inv = np.linalg.inv(A)
# array([[ 1., -1.],
#        [-1.,  2.]])

A_inv @ A     # the identity, up to floating-point error
```

When the plane collapses, the transformation **destroys information**. Two distinct points of the
original plane end up in the same position, and no matrix can separate them again, since it would
have no criterion for deciding where each point came from.

Under those conditions the matrix is called **singular** and admits no inverse.

```python
B = np.array([[2, 4],
              [1, 2]])       # the second column is twice the first

np.linalg.inv(B)
# LinAlgError: Singular matrix
```

NumPy returns an error rather than an approximate result, which is the preferable behaviour in
practice: a system without a unique solution should signal that explicitly instead of supplying an
arbitrary value.

## Solving systems as inversion

A system of equations $A\vec{x} = \vec{b}$ poses the following question: *which vector, when
transformed by $A$, becomes $\vec{b}$?* It is the transformation in reverse.

```python
b = np.array([5, 3])
np.linalg.solve(A, b)     # array([2., 1.])
```

One practical recommendation bears repeating: although $A^{-1}b$ produces the same result in
mathematical terms, it is preferable to **use `solve` rather than `inv`**. Computing the full
inverse is costlier and numerically less stable than solving the system directly. The difference
only becomes apparent with matrices of considerable size, by which point the cost already matters.
