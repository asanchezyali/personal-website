Almost all applied linear algebra starts in the same place: you have several equations, all linear,
and you want the values that satisfy them at once.

$$
\begin{aligned}
  x_1 + x_2 + x_3 &= 3\\
  x_1 - x_2 + 2x_3 &= 2\\
  x_2 + x_3 &= 2
\end{aligned}
$$

Written that way it looks like a puzzle of substitutions. Written the other way — a **matrix** $A$
holding the coefficients and a **vector** $\vec{b}$ holding the right-hand sides — it is a single
question:

$$A\vec{x} = \vec{b}$$

And that question has a one-line answer.

## Setting the system up

Each row of $A$ is one equation. The vector $\vec{b}$ is the numbers on the other side of the
equals sign:

```python
import numpy as np

A = np.array([[1,  1, 1],
              [1, -1, 2],
              [0,  1, 1]])
b = np.array([3, 2, 2])
```

Note that the coefficients that aren't there still take up space: the third equation has no $x_1$,
so its first entry is a `0`. A matrix has no gaps.

## Solving it

```python
x = np.linalg.solve(A, b)
```

```python
# array([1., 1., 1.])
```

That's it. But it's worth knowing what happened in there, because it explains why this line is the
right one and other lines that look equivalent are not.

`solve` does **not** compute the inverse of $A$. It factors the matrix into two triangular ones,
$A = LU$, and uses them to solve two chained systems, each trivial because it is triangular. The
work is $O(n^3)$, and underneath it is LAPACK, the linear algebra library that has carried
scientific computing since the nineties.

## What elimination does, step by step

That factorisation is Gaussian elimination, organised. Hit play and watch: every step is one row
operation, and the goal is to leave the identity on the left. When you get there, the right-hand
column **is** the solution.

There's no trick to it: adding a multiple of one equation to another doesn't change the solutions of
the system, and repeating that move gets you to a system simple enough to read the answer off
directly.

## Checking

Never trust a numerical result blindly. Substitute and check:

```python
np.allclose(A @ x, b)
```

```python
# True
```

The `@` operator is the matrix-vector product. And the check is `allclose`, not `==`: in floating
point the exact result almost never comes out exact, and strict equality will hand you `False` over
a $10^{-16}$ error that means nothing.

With two unknowns each equation is a **line**, and solving the system is asking where they cross.

Try driving the determinant to zero. You'll find there are only two ways for that to happen, and
they are exactly the two cases where `solve` cannot give you an answer.

With three unknowns the picture is the same one floor up: each equation is a **plane**, and the
solution is the point where all three meet.

## What if there is no unique solution?

`solve` requires $A$ to be invertible. If one row is a combination of the others, the matrix is
**singular** and the function refuses:

```python
C = np.array([[1,  1, 1],
              [1, -1, 2],
              [2,  0, 3]])

np.linalg.solve(C, np.array([3, 2, 1]))
```

```python
# LinAlgError: Singular matrix
```

Here the third row is the sum of the first two, so it carries no new information: two equations
dressed up as three. What decides this is the **rank**, the number of rows that are genuinely
independent:

```python
np.linalg.matrix_rank(C)
```

```python
# 2
```

With $\operatorname{rank}(A) < n$ there are zero or infinitely many solutions, never exactly one.
Which of the two depends on $\vec{b}$: if it agrees with the dependency, solutions are in surplus;
if it contradicts it, there are none.

Look at the end: a row of zeros appears in the $A$ part. That row is the proof that the third
equation said nothing new. If its right-hand entry ends up non-zero, the system is asking for
$0 = \text{something}$, which is why no solution exists.

For these cases there is `lstsq`, which returns the least-squares solution — the one that is wrong
by the smallest amount — even when `solve` gives up:

```python
x, residuals, rank, sv = np.linalg.lstsq(C, np.array([3, 2, 1]), rcond=None)
```

## The rule of thumb

To solve $A\vec{x} = \vec{b}$, use `solve`. Never `inv(A) @ b`.

```python
x = np.linalg.solve(A, b)      # yes
x = np.linalg.inv(A) @ b       # no
```

Both lines give nearly the same number, but the second does more work (computing the full inverse
costs more than solving the system) and carries more numerical error. And you almost never need the
inverse itself: what you need is its *effect* on a vector, which is exactly what `solve` hands you.
